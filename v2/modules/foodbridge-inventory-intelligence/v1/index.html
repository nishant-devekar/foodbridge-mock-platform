Discovery version inventory-intelligence-v1 — snapshot

Frozen snapshot of the Inventory Intelligence discovery prototype, accepted 2026-08-16, taken per discovery working rule R6 (“an accepted iteration becomes a version”).

This freezes independently of inventory-v1 and raw-material-inventory-v1, which are fidelity ports of the live routes. This one is not a port — it is the decision layer built on top of them.

What it is

Inventory V1 helps a distributor understand what needs attention, what threatens sales, where inventory capital is tied up, what purchasing decisions need review, why an inventory problem exists, and which module owns the next action — while clearly distinguishing verified facts, estimates, uncertainty, and horizon-scoped projections.

Five decisions, not a set of reports:

                    INVENTORY
                        │
        ┌───────────────┼───────────────┐
        ↓               ↓               ↓
     TODAY             BUY            MONEY
 "What matters?"  "What should I do?" "Where is money?"
        │               │               │
        └───────────────┼───────────────┘
                        ↓
                  NOT WORKING
                 "What's wrong?"
                        │
                        ↓
                    LOOK UP
                 "Show evidence"

And underneath every finding, the chain that separates a decision engine from a stock ledger:

OBSERVATION → CAUSE → BUSINESS IMPACT → OWNER → ACTION / HANDOFF

Running it

python3 tools/serve.py 8081     # from the repo root, then open
# http://localhost:8081/screens/inventory-intelligence/index.html

node checks/check-invariants.mjs    # 38 checks, no dependencies

The checks run against this snapshot’s own mock-intel.js and seed, so the frozen version stays verifiable on its own long after the working copy has moved on.

Provenance — what is real and what is simulated

   
Measured, from the source system batch quantities, expiry dates, landed cost, supplier attribution, physical vs traced stock
Simulated 90 days of sales history, selling prices (the source carries no selling price), promised delivery dates, demand signals, the purchase pipeline
Derived everything else — sellability, shortfall, DOH, velocity, capital buckets, margin, return on capital, future position

Margin and return therefore rest on illustrative selling prices, and the UI says so above the figures rather than in a footnote. Replacing them with real prices changes the numbers, not the model.

Known limitations, deliberately frozen with them

Ageing buckets beyond 60 days are empty (the simulation runs 90 days) · the customer book is close to uniform where a real one is power-law · no inventory value history, so no inventory-vs-sales growth · “Working stock” is a residual, not an assessment (Q32) · DOH uses verified stock while the adjacent “on hand” uses physical (Q42).
