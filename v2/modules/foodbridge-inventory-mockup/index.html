Discovery prototype

Inventory Management

Disposable HTML prototypes for the Foodbridge Module Inventory Management module. This round is a fidelity port of two live storefront routes — /inventory and /raw-material-inventory — same structure, same classes, same edge cases, driven entirely by seed data. Nothing here calls a real API, and nothing here is imported by development/. Each route is frozen as its own version.

Known divergences from the live app

Recorded deliberately rather than papered over:
  • Batch dates are stored as offsets, not absolute dates. The seed carries expiryInDays / mfgDaysAgo / createdDaysAgo, resolved to real dates at load. Live the API returns absolute ISO dates — offsets keep the Healthy / Near Expiry / Expired buckets correct however long after freezing this prototype is opened.
  • Product images are placeholder tiles. Live resolves real photos through productImageBaseUrl; discovery has no image host, so each product gets a deterministic initials tile at the same dimensions.
  • The sidebar menu tree is an assumption. No reference screenshot was supplied for this module, so it is carried over from the staff module’s screenshot of the same tenant, with the two inventory routes placed under Inventory. The tenant’s real storefrontMenus is authoritative.
  • AddBatchDrawer is unreachable on /inventory. The live page mounts it but never renders a control that opens it — only /raw-material-inventory has the “Receive Stock” trigger. Reproduced as-is; this looks like a live defect worth raising separately.
  • LiveStockModal is dead code in the live repo — 518 lines imported by nothing. Not ported.
  • Saving in Quick Stock Upload is local. It appends a batch to in-memory state so Batch History reflects the upload, standing in for the real create-batch call plus reloadBatches().
Governed by AMDS. Discovery is HTML-only and disposable (SPEC §3.1) — it produces the decisions that become the SSOTs under development/sources-of-truth/, and is never imported by development/. Working rules: instructions/addendum-001-working-rules.md.
